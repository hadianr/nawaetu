# antislop audit 001: Nawaetu design system

**Date:** 24 November 2026
**Mode:** After (audit of the shipped product). Nothing in `src/` was changed.
**Rulebook:** [miqdadbadjuber/anti-slop](https://github.com/miqdadbadjuber/anti-slop) core `antislop.md` (R-01 to R-40) plus the `antislop-ui`, `antislop-human`, `antislop-layoutmobile`, `antislop-copywriting` and `antislop-code` skills.
**Direction file:** `design.md` (present, so R-37 is satisfied and every finding below is judged against Nawaetu's own contract as well as antislop).
**Scope:** tokens (`src/context/themes.ts`, `src/app/globals.css`), primitives (`src/components/ui`), icon registry, fonts, and a full-codebase pattern sweep of `src/**/*.tsx` and the `en`/`id` translations.

Priority follows the antislop tiers: Hard Gate = **HIGH**, Purpose-Gate = **MEDIUM**, Quality Lock = **LOW**.

---

## Verdict

Nawaetu is **not** an AI-slop design. It has a real direction (`design.md`), a semantic token layer applied to five themes, a single icon registry, a 44px button target, a light default chosen for the audience, a reduced-motion fallback, a reduced-transparency fallback, and honest copy: no fake statistics, testimonials, trust badges, generic FAQ, or buzzwords were found.

What it has instead is **drift**: the codebase has outgrown its own `design.md`. Most findings are places where feature code bypasses the contract (raw Lucide imports, ad-hoc blur, 9-10px text, off-palette colors) and where `globals.css` patches those bypasses with `!important` attribute selectors instead of fixing them at the source. Six findings are Hard Gate failures and block a clean Delivery Gate.

## Findings

### HIGH: Hard Gate

**1. Destructive buttons fail contrast in every dark theme.** *(R-25)*
`Button` `destructive` is `bg-destructive text-white`; dark themes set `--color-danger` to `248 113 113` (#F87171). White on #F87171 is **2.77:1** (needs 4.5:1) in Emerald, Midnight and Sunset. The `dark:bg-destructive/60` fallback never applies (see #8).
`src/components/ui/button.tsx:32`, `src/context/themes.ts` (`danger` default).

**2. Primary-colored text fails contrast on Midnight cards.** *(R-25)*
138 places use `text-[rgb(var(--color-primary))]`. Light themes remap it to `primary-strong` in `globals.css:474`, dark themes do not. Midnight primary #3B82F6 on its surface #1E293B is **3.98:1**. It passes on the canvas (5.47:1), so this fails exactly where content sits: inside cards.

**3. Off-palette streak and stats colors fail contrast in light themes.** *(R-25, R-29)*
`sky-400`, `violet-400` and `orange-400` are hardcoded and ignore the theme. On white they measure **2.14:1**, **2.72:1** and **2.26:1**, failing even the 3:1 non-text bar for icons.
`src/components/streak/StreakWeek.tsx:44,69`, `src/components/StreakBadge.tsx:222`, `src/components/stats/StatsOverview.tsx:156`, `src/components/auth/LoginNudge.tsx:86`.

**4. Input and control borders are effectively invisible.** *(R-25 non-text, `antislop-human` "Non-Text Contrast")*
Form-field boundaries need 3:1 (WCAG 1.4.11). Measured border on surface: Emerald/Midnight/Sunset **1.05-1.08:1** (the dark `--border` is the border token at 16% alpha), Daylight **1.33:1**, Blossom **1.44:1**. A low-vision user cannot find the search field or the zakat calculator inputs.
`src/app/globals.css:109-110`, `src/context/themes.ts` (`border`).

**5. Text drops to 6-11px across the app.** *(R-03, R-25; `design.md` "Avoid 9-10px for meaningful information")*
418 occurrences: `text-[10px]` 226, `text-[9px]` 103, `text-[11px]` 52, `text-[8px]` 22, `text-[7px]`/`[6px]` 15. The dhikr counter label is 7px on mobile (`src/components/dhikr/DhikrDisplay.tsx:135`). On top of that, `globals.css:336-343` **shrinks** `text-xs` to 11.2px and `text-sm` to 12.8px on screens at or below 390px, i.e. it makes text smaller on exactly the budget phones most users hold.
Worst files: `RamadhanWrappedCard`, `MissionDetailDialog`, `FastingDayModal`, `PrayerCheckInWidget`, `GamificationStats`.

**6. Em dashes in user-facing copy.** *(R-02)*
About 40 strings across both locales plus the app name itself:
- `src/app/_manifest.ts:28` and `src/components/DynamicTitle.tsx:33,37`: "Nawaetu — Worship with Intention" (the install name and every tab title).
- `src/data/translations/{en,id}/other.ts:277,278,594,609,616`, `ramadhan.ts:26,27,36,37`, `hijri-calendar.ts:94-96`, `fasting-tracker.ts:37,40`, `quran.ts:81,86`, `rewards.ts:10,26`, `stats.ts:87`.
- `src/app/about/page.tsx:109`, `src/app/api/ramadhan/insight/route.ts:65`.
- `—` as the empty-value glyph in `src/components/stats/QuranStatsCard.tsx:43,51,59`.
Carve-out applied: em dashes inside licensed HadeethEnc/QuranEnc text and code comments are **not** counted. The attribution dash before a hadith source (`— HR. Bukhari`) is listed for the owner's decision under R-37, since it is a quotation convention.

**7. Buttons do not show a pointer cursor.** *(R-39)*
Tailwind v4's preflight resets `button` to `cursor: default`, and no base rule restores it. 213 `<button>` elements, 73 explicit `cursor-pointer`. R-39 wants it set once in the base layer.
`src/app/globals.css` `@layer base`.

**8. Every `dark:` utility is dead code.** *(R-34)*
`@custom-variant dark (&:is(.dark *))` waits for a `.dark` class that nothing sets; themes use `data-color-mode`. The 10 `dark:` utilities in the shadcn primitives (destructive button, outline button, input fill, aria-invalid rings) never apply, so dark themes render the light-mode recipe of those controls.
`src/app/globals.css:5`, `src/components/ui/button.tsx`, `input.tsx`.

**9. Broken color tokens silently drop backgrounds.** *(R-34, R-26)*
- `rgb(var(--color-secondary))` resolves to `rgb(rgb(...))` because `--color-secondary` is already a full color in `@theme`. The About page CTA gradient and section background, and the profile header gradient, fall back to nothing. `src/app/about/page.tsx:151,283`, `src/components/profile/ProfileHeader.tsx:42`.
- `color-mix(in srgb, var(--color-primary-light) ...)` mixes raw RGB channels (`61 164 118`), not a color, so all 15 declarations in `src/components/ramadhan/RamadhanHeroCard.tsx` are invalid and the hero's mesh gradient never paints.

**10. Inputs are 36px tall; the counter has a keyboardless surface.** *(R-03, R-32)*
`Input` is `h-9` (36px) while `design.md` sets 44px for interactive targets; the global 44px rule in `globals.css:349-354` only covers `button`, `a` and `[role=button]`. Separately, Zen mode's full-screen tap area is a `div` with `onClick` (`src/components/dhikr/DhikrZenMode.tsx:74`); confirm a focusable increment control exists in Zen mode, otherwise keyboard and switch users cannot count there.

### MEDIUM: Purpose-Gate

**11. Backdrop blur in 65 files.** *(R-10; `design.md` "Glass ... using the shared `glass-surface` class")*
118 `backdrop-blur` utilities against 13 uses of the sanctioned `glass-surface`. Blur sits on cards (`ZakatFitrahCard`, `KhatamanProgress`, `IntentionCard`), dialogs (`DhikrHistory` uses `backdrop-blur-3xl`), sticky headers, the chat input and the About sections at once. Many sit on an opaque `bg-[rgb(var(--color-surface))]`, where blur paints nothing and only costs GPU time on low-end Android. R-10 caps it at 1-2 elements.

**12. Sparkles as a default icon.** *(R-04)*
96 references. Some are defensible (Lailatul Qadr, the night itself), but it also marks "early mission", About, insights, check-in success, and is used **spinning as a loading indicator** in `src/components/StoryShareModal.tsx:262`. The registry also aliases the `✨` emoji to it (`src/lib/icon-names.ts:9`). Write the relevance down per use or swap for a content icon.

**13. 112 files import Lucide directly instead of `AppIcon`.** *(R-04; `design.md` "AppIcon: the only shared icon entry point")*
Lucide itself passes the purpose gate because `design.md` names it and gives the reason (consistency). The bypass is the problem: raw imports skip the registry's size, tone and `aria-hidden` handling, which is how `ZapIcon` (lightning, an R-04 icon) reached the stats grid.

**14. A decorative mesh gradient that animates forever.** *(R-01, R-19; `design.md` "Avoid persistent glow, pulse, or decorative motion")*
`RamadhanHeroCard` stacks a 135deg gradient, three radial orbs, `backdrop-blur-xl` and `animate-gradient-shift` (4s, infinite). The reduced-motion fallback stops it, so this is a purpose problem, not an a11y one. Today it is also invisible (see #9). Either give it one written job (e.g. the gradient deepens through the three 10-day periods, which the code hints at) or remove it.

**15. Rainbow stat tiles.** *(R-01, R-29)*
The four stats tiles each get their own wash: orange, primary, yellow, violet (`src/components/stats/StatsOverview.tsx:136-160`). That is five hues on one screen outside the token set, with no hierarchy reason. Use the primary for the one focal stat and neutral surfaces for the rest.

**16. Uppercase tracked labels in 73 files.** *(R-06; `design.md` "Uppercase tracking is for short metadata labels only")*
170 `uppercase ... tracking-wider` lines. `tracking-wider` is not the extreme spacing R-06 bans, but at this dose, and combined with 9-10px text (#5), it becomes the eyebrow-label house look. Includes a hardcoded, untranslated `HARI KE-{viewDay} — LOKASI SHOLAT WAJIB` in `src/components/ramadhan/DailyPrayerTracker.tsx:138`, which also breaks the bilingual rule in `AGENTS.md`.

### LOW: Quality Locks

**17. `globals.css` patches components by matching class strings.** *(R-33 in spirit, R-31; `design.md` "must not branch on a theme name")*
`[data-theme="daylight"] [class*="from-[rgb(var(--color-primary))"]:not([class*="w-5"], ...)`, `[class*="text-[rgb(var(--color-primary))]"]`, and a forced `box-shadow: var(--shadow-card) !important` on any `rounded-xl border` in light mode (`globals.css:186-198, 474-523`). No script rewrites files, so R-33 is not literally violated, but these are runtime patches: brittle to any class reorder and the reason #2 only got half fixed. Move each into the token or the component that owns it.

**18. Global utility redefinitions on small screens.** *(R-03, `antislop-layoutmobile` "Fixed Pixel Type")*
`.px-3`, `.py-3`, `.gap-3`, `.text-xs`, `.text-sm` are silently redefined at 390px and below (`globals.css:320-344`). A component cannot know its spacing from its own classes. Delete the block and let components set responsive values.

**19. Emoji in product copy.** *(`design.md` "No emoji ... as UI chrome", `antislop-copywriting`)*
`✨ Berhasil!`, `✅ Sip!`, `Alhamdulillah! ✅` toast fallbacks (`GuestSyncManager.tsx:188,373`, `PrayerCheckInWidget.tsx:237`), `☀️` in push titles (`src/lib/notifications/push-copy.ts:19,51`) and greetings (`src/lib/time-context.ts:109`).

**20. One generic CTA.** *(R-15)*
`intention_start_now: "Mulai Sekarang"` (`src/data/translations/id/other.ts:681`). Name the action: "Tulis niat hari ini".

**21. No declared dials.** *(Part 3 Liveliness)*
`design.md` sets character and tokens but no dial line, so there is nothing to hold motion or rhythm drift (#11, #14) against. Suggested Design Read, for the owner to confirm:
> Reading this as: a daily worship companion PWA for Indonesian Muslims, in a calm, warm emerald-and-paper language, dial ENERGY 1 / RHYTHM 2 / MOTION 1.

**22. Dead and duplicated CSS.** *(`antislop-code` "Decorative Separators", "Empty Labels")*
Two identical `prefers-reduced-motion` blocks (`globals.css:119` and `:217`), an empty rule (`:444-446`), `=====` banner comments, and a stale header calling Daylight a "Light Glassmorphism Design System" with "white/65 frosted glass" surfaces, which is no longer true.

**23. `<html lang="id">` is static.** *(R-39)*
`LocaleContext` corrects `lang` after hydration, so English users get the right value in the browser, but the server HTML and anything that reads it before hydration (crawlers, some screen readers on first load) see `id`.
`src/app/layout.tsx:180`.

## Method and limits

- Contrast: every token pair in all five themes was computed with the WCAG 2.x formula by `anti-slop/theme-contrast.mts` (`node anti-slop/theme-contrast.mts`), and the failing pairs were re-checked with antislop's own `contrast-check.py`. Alpha borders were blended over their surface before measuring.
- Patterns: ripgrep sweeps over `src/` excluding tests; every count above is reproducible from the pattern named next to it.
- **Not done:** R-35 (running the app and clicking through every control) and a 320px overflow pass were not performed. This is a static code audit, so R-03 overflow and R-32 tab order are unverified, not passed.

Report page: https://claude.ai/artifact/DZGNrkbVb5MpEgpQJCHFa8

Confirmed in the browser: #2 (3.59:1 on `/quran`, Midnight), #5 (120 of 121 text elements under 12px on `/hadith`, 118 of 119 on `/dua`; 7px on `/`, `/dhikr`, `/stats`), #7 (39 of 46 controls without a pointer cursor on a surah page, 30 of 36 on `/missions`).
